# Jazz Setlist

Setlist manager for a jazz drummer: per-user tune arrangements, show setlists with set breaks, and a metronome per tune.

## Stack

- JavaScript only (no TypeScript). ES modules everywhere.
- Frontend: Svelte 5 (runes) SPA, hash routing (`src/client/lib/router.js`), plain CSS with tokens in `src/client/app.css`.
- Backend: Hono on Cloudflare Workers. Hono JSX (`.jsx`, `jsxImportSource: hono/jsx`) for server-rendered HTML; the page shell is `src/server/shell.jsx`.
- DB: Cloudflare D1 + Drizzle ORM (`src/db/schema.js`), migrations in `drizzle/` generated by drizzle-kit.
- Validation: Zod (`src/shared/validation.js`), shared by server and any client code.
- Build/dev: Vite 8 + `@cloudflare/vite-plugin` (runs the Worker inside `vite dev`) + `@sveltejs/vite-plugin-svelte` + `vite-plugin-pwa`.
- Tests: Vitest. Lint: ESLint 10 flat config (`eslint.config.js`) with `eslint-plugin-svelte`.

## Layout

```
src/
  server/      index.jsx (Hono app + shell route), shell.jsx, middleware/auth.js, routes/*.js, lib/http.js
  db/          schema.js (all tables), index.js (createDb)
  shared/      attributes.js (enums, labels), validation.js (Zod), setlist.js (numberSets, moveItem)
  client/      main.js, App.svelte, app.css, pages/, components/, lib/ (api, router, metronome)
drizzle/       SQL migrations (generated; do not hand-edit)
```

## Commands

```bash
pnpm dev                # Vite + Worker on http://localhost:5188
pnpm test               # Vitest
pnpm lint               # ESLint
pnpm check              # lint + test + build — run before calling work done
pnpm db:generate        # drizzle-kit generate after editing src/db/schema.js
pnpm db:migrate:local   # apply migrations to local D1 (.wrangler/state)
pnpm db:migrate:remote  # apply to production D1
pnpm release            # build, apply remote migrations, wrangler deploy (manual deploy)
pnpm icons              # re-render favicon + PWA PNGs from public/favicon.svg (ImageMagick)
pnpm import:polynome <backup.pln> <email> [--local|--remote]   # PolyNome backup -> tunes + setlists
```

`pnpm deploy` is pnpm's built-in workspace command, not a script; never name a script `deploy`.

## Deployment (GitHub Actions → Cloudflare)

- Repo: `git@github.com:cyface/jazz-setlist.git`, branch `main`. Everything (Worker + D1 `jazz-setlist`) lives in the timlwhite Cloudflare account `16805f1fb394761354e4f3f30bafa8c4`, set by `account_id` in `wrangler.jsonc`. Never deploy to another account.
- `.github/workflows/ci.yml`: every PR runs `pnpm check`.
- `.github/workflows/deploy.yml`: every push/merge to `main` runs `pnpm check`, then `pnpm release:ci` (applies pending D1 migrations, then `wrangler deploy`). Needs repo secret `CLOUDFLARE_API_TOKEN` (timlwhite account: Workers Scripts Edit + D1 Edit).
- Work on a branch and merge by PR (`gh pr merge --squash`); head branches are deleted on merge. Merging to `main` deploys to production.
- `pnpm build` writes `dist/client` (assets) and `dist/jazz_setlist/wrangler.json`; `wrangler deploy` picks up that generated config automatically.
- Local D1 state under `.wrangler/state` is keyed by `database_id`; if the ID changes, rerun `pnpm db:migrate:local`.

## Auth (Cloudflare Access / Zero Trust, same pattern as cyface-invoice)

- Cloudflare Access protects the whole custom domain. The Worker reads `CF-Access-Authenticated-User-Email` and auto-provisions a `users` row (`src/server/middleware/auth.js`).
- Local dev: `.env` (copy from `.env.example`) sets `DEV_AUTH_EMAIL`; it is honored only for `localhost`/`127.0.0.1`. Do not create a `.dev.vars`: when it exists, wrangler ignores `.env`.
- `workers_dev` and `preview_urls` are `false` so the Worker is reachable only through Access. Never enable them: the header is trusted, so a public URL would let anyone impersonate a user.
- Every query on `arrangements` / `setlists` filters by `user_id`. Setlist item writes verify each `arrangementId` belongs to the user.

## Data model

- `arrangements`: title, composer, musical_key, tempo (bpm), beats_per_bar, `feel` (swing|straight), `drum_implement` (sticks|brushes), `drums_entry` (top|later) + `drums_entry_note`, `solo_order` (JSON), notes.
- `solo_order` entries: `{type:'solo', instrument}`, `{type:'trade', instruments:[≥2], bars:2|4|8}`, `{type:'over_head', instrument}` (e.g. drums solo over the head out). Instruments are free text, lowercased; suggestions in `INSTRUMENTS`.
- `setlists` + `setlist_items` (`kind` tune|break, `position`). `setlists.archived_at` (null = active) archives a setlist without deleting it; the list page has Active / Archived tabs (`#/setlists`, `#/setlists/archived`). `PUT /api/setlists/:id/items` replaces all items in one D1 batch. Deleting an arrangement cascades out of setlists.
- Adding an attribute value: extend the enum in `src/shared/attributes.js` (+ `LABELS`), add an icon branch in `Icon.svelte`, and a badge color token in `app.css`. Enum columns are TEXT, so no migration is needed for new values.

## API

`/api/me`, `/api/arrangements[/:id]` (GET/POST/PUT/DELETE), `/api/setlists[/:id]` (GET/POST/PUT/DELETE), `PUT /api/setlists/:id/items`, `PUT /api/setlists/:id/archived` (`{ archived: boolean }`). Errors are `{ error }` or `{ error, issues: [{path, message}] }` on 400.

## Frontend conventions

- Icons are hand-drawn inline SVG in `src/client/components/Icon.svelte`; every attribute shows as an icon (with label, or with tooltip/`aria-label` in compact mode) via `TuneBadges.svelte`.
- Metronome: `src/client/lib/metronome.js` is a Web Audio lookahead scheduler (clicks scheduled on the audio clock, beat squares lit by `requestAnimationFrame`). Keep timing logic in pure functions (`planBeats`, `isAccent`, `tapTempo`) and test them. Space bar toggles play; screen wake lock is held while playing.
- Dark mode is required. Every color is a token on `:root` in `app.css` written as `light-dark(<light>, <dark>)`; never hardcode colors in components, and give every new token both values.
- Theme: `color-scheme: light dark` follows the OS; the top-bar toggle (System → Dark → Light) sets `data-theme` on `<html>` and stores it in localStorage (`src/client/lib/theme.js`). `THEME_BOOT_SCRIPT` (`src/shared/theme.js`) is inlined in the shell `<head>` so the saved theme applies before first paint. Check UI changes in both themes.
- Production asset names are fixed (`/assets/app.js`, `/assets/app.css`, cache-busted by `?v=<package version>`) because the Hono shell references them. Bump `package.json` version on each release.
- PWA (setup mirrors cyface-invoice): `vite-plugin-pwa` in `vite.config.js` (client environment only) builds `manifest.webmanifest`, `sw.js` and precaches `/assets/*` + favicons; `?v=` is ignored when matching the precache. There is no index.html, so the shell links the manifest (production only, `crossorigin="use-credentials"` for Access) and `main.js` registers `/sw.js`. Navigations are NetworkFirst (cached shell only offline) so an expired Access session still redirects to the login. Icons are rendered from `public/favicon.svg` (`pnpm icons`). `InstallPrompt.svelte` shows a phone-only install banner; its logic is in `lib/install.js`. Access bypass rules for the static PWA paths are listed in `wrangler.jsonc`.

## PolyNome import (`scripts/polynome/`)

Imports a PolyNome Pro backup (`.pln`, git-ignored) as tunes and setlists. Pipeline: `extract.py` (decodes the NSKeyedArchiver plist via `unarchive.py`, maps preset names to canonical titles in `CANON`; the rest of a name is cue text) → `transform.py` (emoji cues → fields: 🥢 sticks, 🖌 brushes, 🎤 drum solo, 🐟 bass, 💹 trading, 🚫🥁 drums later, 🇧🇷/📏 straight; tempo from the newest standalone preset; per-tune solo orders in `SOLOS`; all setlists but the active one archived) → `to-sql.js` (validates with the app's Zod schemas, emits idempotent SQL keyed on the user's email). Output goes to `scripts/polynome/out/` (git-ignored). A new tune name in a backup needs adding to `CANON` (extract prints `UNMAPPED` setlist items). Run Python with `-I`.
